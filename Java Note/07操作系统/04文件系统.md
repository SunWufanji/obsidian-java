# 文件系统

## 1. 硬链接和软链接有什么区别？

### 先说场景

有时候我们想给一个文件起多个“入口”。

比如：

- 一个文件想在多个目录里都能访问
- 想做一个快捷入口
- 想保留原文件位置不变，但从别的地方也能打开

这时候就会遇到硬链接和软链接。

### 大白话解释

可以先这样理解：

- **硬链接**：相当于同一个人有两个正式名字，两个名字都直接指向同一个实体
- **软链接**：相当于你手里有一张写着别人住址的小纸条，靠这张纸条去找原目标

所以它们最大的区别就是：

- 硬链接更像“再起一个并列名字”
- 软链接更像“做一个跳转指针”

### 什么是硬链接？

硬链接本质上是给同一个文件内容再增加一个目录项。

多个硬链接共享同一个 inode，也就是说，它们本质上指向的是同一个文件实体。

这意味着：

- 改其中一个，另一个看到的内容也会变
- 删掉其中一个名字，文件不一定消失
- 只有所有硬链接都删掉，并且没有进程占用时，文件内容才真正被回收

### 什么是软链接？

软链接可以理解成一个“特殊文件”，里面存的是目标文件的路径。

访问软链接时，系统会根据这条路径再去找真正的目标文件。

所以软链接更像 Windows 里的快捷方式。

### 两者区别

| 对比点 | 硬链接 | 软链接 |
|--------|--------|--------|
| 指向方式 | 直接指向同一个 inode | 指向目标路径 |
| 删除源文件后 | 只要还有别的硬链接，文件还在 | 源文件删了，链接就失效 |
| 能否跨文件系统 | 不能 | 可以 |
| 能否链接目录 | 一般不能 | 可以（很多系统支持） |
| 本质 | 同一个文件的多个名字 | 一个单独的链接文件 |

### 为什么硬链接不能跨文件系统？

因为 inode 是文件系统内部的概念。

硬链接要直接指向 inode，而不同文件系统里的 inode 不是同一套管理范围，所以没法跨过去直接连。

### 为什么软链接更灵活？

因为它只记录路径。

路径本身不关心底层 inode 在哪个文件系统，所以它更容易跨目录、跨文件系统使用。

### ⚠️ 面试易错点

- **硬链接不是“复制一份文件”**，它只是多了一个文件名入口。
- **软链接不是目标文件本身**，它只是保存目标路径。
- **删掉源文件后，硬链接通常还能访问，软链接通常会失效**。
- **硬链接一般不能跨文件系统，也不能随便链接目录**。

### 面试回答模板

硬链接和软链接的核心区别在于指向方式不同。硬链接是给同一个文件增加新的目录项，多个硬链接共享同一个 inode，本质上是同一个文件的多个名字；软链接则是一个单独的链接文件，里面保存的是目标文件的路径。

因此，删除原文件后，如果还有其他硬链接，文件内容依然存在；而软链接通常会失效。硬链接不能跨文件系统，软链接可以跨文件系统，也更灵活。

### 面试简答版

硬链接是同一个文件的多个名字，直接指向同一个 inode；软链接是保存目标路径的链接文件。

硬链接删一个名字不影响文件本体，软链接删掉源文件后通常会失效。

## 2. 什么是预读？

### 先说场景

你在程序里读文件时，操作系统很多时候不会傻乎乎地“你读 4KB，我就只给你搬 4KB”。

它经常会偷偷多读一点。

这就是预读。

面试官问这题，通常是在考你：

**文件系统为什么敢提前读，以及这样做到底图什么。**

### 大白话解释

你可以把预读理解成：

**系统猜你下一步大概率还会继续往后读，所以干脆先把后面的数据也带上来。**

像你在看一本书，刚翻到第 10 页，别人直接把第 11 页、第 12 页也先摊开准备好。

这样你下一次翻页时，就不用再等了。

### 它到底是什么？

预读（Read Ahead）是文件系统和内核常见的一种优化机制。

当系统发现你在**顺序读取文件**时，它会提前把后续的一部分数据从磁盘读到内存里，通常放进 **Page Cache**。

这样你后面继续读时，很可能直接命中缓存，不需要再真的访问磁盘。

### 为什么预读有效？

因为磁盘 I/O 很慢，而内存访问很快。

如果系统判断你是顺序读：

- 第一次读：可能真的要碰磁盘
- 后面的读：有机会直接命中缓存

所以预读的核心目的就是：

- 减少磁盘 I/O 次数
- 提高顺序读性能
- 降低应用等待时间

### 它什么时候更容易触发？

最典型的就是：

- 顺序读大文件
- 流式读取
- 日志扫描
- 视频 / 图片 / 数据文件连续读取

这类场景里，系统很容易判断出：

> 你不是随便跳着读，而是在一段一段往后读。

于是就会积极预读。

### 它什么时候效果不好？

如果你的访问方式是：

- 随机读
- 跳着读
- 读一点就换位置

那系统预读的很多内容，可能你根本用不上。

这时候预读就可能变成“好心办坏事”。

这也正好会引出下一题：**缓存污染**。

### 预读和缓存是什么关系？

预读本身通常不是“直接交给用户程序”，而是：

**先把未来可能会用到的数据放进缓存里。**

所以预读常常和 **Page Cache** 绑在一起出现。

你可以简单记成：

- 预读：提前搬
- Page Cache：先存着

### ⚠️ 面试易错点

- **预读不是应用程序手动做的事**，很多时候是内核和文件系统自动优化
- **预读最适合顺序读，不适合随机读**
- **预读并不是“读得越多越好”**，读多了可能浪费内存、污染缓存

### 面试回答模板

预读是文件系统和操作系统的一种性能优化机制。当系统发现进程在顺序读取文件时，会提前把后续一部分数据从磁盘读入内存缓存中，通常放到 Page Cache 里。这样应用后续继续读取时，就可能直接命中缓存，减少磁盘 I/O 次数，提高顺序读性能。预读更适合顺序访问场景，而在随机访问场景下效果可能较差，甚至会带来缓存污染。

### 面试简答版

预读就是系统发现你在顺序读文件时，提前把后面的数据也读到缓存里。这样后续读取更快，但如果访问很随机，预读效果就不好，还可能造成缓存污染。

## 3. 什么是缓存污染问题？

### 先说场景

缓存本来是帮你加速的。

但有时候系统把一大堆“你其实根本不会再用”的数据塞进缓存里，反而把真正热点数据挤出去了。

这就叫缓存污染。

### 大白话解释

你可以把缓存想成办公桌。

桌子空间有限，本来应该放你手头最常用的文件。

结果有人一次性搬来一大摞你只看一眼的旧资料，把你正在用的资料都挤到地上了。

这就是缓存污染：

**低价值数据占了缓存，高价值数据反而被赶出去。**

### 在文件系统里它通常怎么出现？

最常见的场景就是：

- 顺序扫描超大文件
- 批量读取日志
- 备份程序扫盘
- 流式处理一次性数据

这些数据有个共同特点：

**读过一次，短时间内大概率不会再读第二次。**

但系统可能还是会把它们装进 Page Cache。

结果就是：

- 大量“一次性数据”占满缓存
- 原本热点文件页被淘汰
- 真正常用的数据下一次访问又得重新走磁盘

### 它为什么会发生？

因为缓存机制本质是在“猜未来”。

系统会觉得：

> 既然你刚刚读了这些内容，可能等会还会再用。

但如果这个判断错了，就会把并不值得缓存的数据留下来。

预读也可能加剧这个问题：

- 本来你只读一点
- 系统顺手又预读一大片
- 而这些预读内容根本没被真正使用

于是缓存更容易被污染。

### 缓存污染会带来什么后果？

- Page Cache 命中率下降
- 热点数据被挤出缓存
- 磁盘 I/O 变多
- 整体性能反而下降

尤其在内存不那么宽裕的机器上，这个问题会更明显。

### 怎么缓解？

思路核心就一句话：

**尽量别把“一次性数据”当成“热点数据”缓存起来。**

常见办法有：

- 合理控制预读
- 使用更合适的读策略
- 某些场景下提示系统这些数据不需要长期缓存
- 对流式 / 扫描式大文件访问采用更合适的 I/O 方式

面试里你不用讲得太底层，知道方向就够了。

### ⚠️ 面试易错点

- **缓存污染不是“缓存坏了”**，而是缓存里装了不该装那么久的数据
- **顺序扫大文件是典型诱因**
- **预读和缓存污染经常一起出现，一个是优化，一个是副作用**

### 面试回答模板

缓存污染指的是一些访问价值不高、短时间内不会再次使用的数据进入缓存，并把真正的热点数据挤出缓存，导致缓存命中率下降。在文件系统中，这种情况常见于顺序扫描大文件、日志批量处理、备份扫盘等场景。由于这些数据往往只访问一次，如果仍然大量进入 Page Cache，就可能造成缓存污染，最终增加磁盘 I/O，降低整体性能。

### 面试简答版

缓存污染就是“不常用的数据占了缓存，把真正常用的数据挤出去了”。文件系统里最常见的场景是顺序扫大文件或一次性流式读取。

## 4. 什么是 Page Cache？它是怎么产生和释放的？

### 先说场景

你会发现，很多文件第一次读很慢，第二次读就快了很多。

这背后最常见的原因，就是 **Page Cache**。

所以这题其实在问：

**文件数据为什么会“读过一次就像记住了”，又为什么过一阵子它又可能“忘了”。**

### 大白话解释

你可以把 Page Cache 理解成：

**操作系统替文件系统准备的一层文件页缓存。**

文件内容不是每次都直接从磁盘现拿，而是会先尽量缓存在内存里。

这样以后再访问同一段文件数据时，就能少碰磁盘。

### 它是什么？

Page Cache 本质上是内核利用内存保存的**文件数据缓存**。

它主要缓存的是文件内容对应的页。

你可以简单理解成：

- 磁盘上存的是原始文件
- 内存里留一份最近访问过的“热门页”
- 下次再读时优先从这份缓存拿

### 它是怎么产生的？

最常见有两种来源：

#### 1. 读文件时产生

程序调用 `read()` 读取文件时：

- 如果缓存里没有
- 操作系统就从磁盘把对应文件页读进内存
- 同时把这些页放进 Page Cache

所以第一次读通常慢一些，后面再读就可能直接命中。

#### 2. 预读时产生

如果系统判断你在顺序读，它可能不只读当前页，还会把后续页也提前装进缓存。

这也是为什么预读和 Page Cache 常常绑在一起讲。

#### 3. mmap 也会和它有关

如果文件通过 `mmap` 映射到进程虚拟地址空间，访问文件页时底层通常也会和 Page Cache 关联起来。

你可以理解成：

`mmap` 不是绕开文件缓存，而是换了一种访问文件页的方式。

### 它的作用是什么？

Page Cache 的核心作用就是：

- 减少磁盘 I/O
- 提高文件读写性能
- 让热点文件数据更快被访问

尤其适合：

- 频繁读取同一文件
- 顺序读
- 热点资源反复访问

### 写文件时和它有关系吗？

有。

写文件时，很多系统也不会每次都立刻把数据同步刷到磁盘。

常见做法是：

- 先写到内存中的缓存页
- 把这些页标记成脏页（dirty page）
- 之后再由内核异步回写到磁盘

所以 Page Cache 不只是读缓存，也和写回机制有关系。

### 它什么时候会被释放？

Page Cache 不是“永久记住”。

它通常会在这些情况下被回收：

#### 1. 内存紧张

当系统发现可用内存不够时，会回收一部分不那么重要的缓存页。

因为缓存本质上是“能加速最好，但必要时可以丢”的东西。

#### 2. 长时间没再访问

如果某些缓存页很久没用了，系统可能把它们淘汰掉，给更热点的数据腾位置。

#### 3. 脏页写回后可回收

写文件产生的脏页，在真正刷盘完成后，也就更容易被后续回收。

### 它和缓存污染是什么关系？

Page Cache 很有用，但如果装进来的大多是“一次性读过就不再访问”的数据，就可能造成缓存污染。

所以你可以把前一题和这一题连起来记：

- Page Cache：加速器
- 缓存污染：加速器里塞了不该塞的东西

### ⚠️ 面试易错点

- **Page Cache 缓存的是文件页，不是普通程序堆内存**
- **它不只是读有关系，写回磁盘也和它有关**
- **mmap 通常也会和 Page Cache 关联**
- **缓存能提升性能，但不是永久保留，内存紧张时会被回收**

### 面试回答模板

Page Cache 是操作系统利用内存为文件系统建立的一层文件页缓存，主要用于缓存最近访问过的文件数据。程序读取文件时，如果数据不在缓存中，系统会先从磁盘把对应页读入内存，并放入 Page Cache；后续再次读取时，就可能直接命中缓存。顺序读取场景下，预读也会提前把后续页放入 Page Cache。写文件时，数据也可能先进入缓存并形成脏页，之后再异步刷回磁盘。Page Cache 会在内存紧张、页面长时间未访问或脏页写回后被系统回收。

### 面试简答版

Page Cache 就是操作系统给文件系统准备的一层文件页缓存。读文件时会把文件页读进来缓存，后面再读就可能直接命中；写文件时也可能先写进缓存再异步刷盘。内存紧张或页面不再热门时，这些缓存页会被回收。
