# Class 文件与类加载

## 1. JVM 有哪些类加载器？它们如何分工？

现代 JDK 的实现细节与 Java 8 有变化，但面试中通常按三层理解：

- **Bootstrap ClassLoader**：由 JVM 实现，加载核心类库，例如 `java.lang.*`。
- **Platform ClassLoader**：Java 9+ 中取代早期的 Extension ClassLoader，加载平台类库。
- **Application ClassLoader**：加载应用 classpath/module path 中的业务类，通常是开发者最常接触的默认加载器。
- **自定义 ClassLoader**：插件化、隔离加载、热部署、加密类等场景使用。

类的唯一身份由“**全限定类名 + 加载它的类加载器**”共同决定；同名类被不同加载器加载，也可能被 JVM 视为不同类型。

## 2. 什么是双亲委派模型？为什么需要它？

一个类加载器收到加载请求时，通常先让父加载器尝试加载；父加载器无法完成时，子加载器才自己查找并定义类。

好处：

- 避免同一个类被重复加载；
- 防止业务代码伪造 `java.lang.String` 等核心类，保证核心 API 的一致性和安全性。

它不是不可打破的铁律。SPI（如 JDBC 驱动加载）、应用服务器隔离、模块化框架等会根据需求采用线程上下文类加载器或自定义委派逻辑。

## 3. 类加载过程有哪些阶段？

完整生命周期可记为：**加载 → 连接（验证、准备、解析）→ 初始化 → 使用 → 卸载**。

- **加载**：找到字节码，生成 `Class` 对象；
- **验证**：确认字节码合法、安全；
- **准备**：为静态变量分配内存并设默认值；
- **解析**：把常量池中的符号引用替换为直接引用；
- **初始化**：执行 `<clinit>`，即静态字段赋值和静态代码块；
- **使用、卸载**：程序实际使用，满足条件时随类加载器一起卸载。

⚠️ 准备阶段 `static int x = 1` 的 `x` 先是默认值 0，真正赋值 1 在初始化阶段。

## 4. 类加载机制有哪些特点？

- **按需加载**：不是程序启动时把所有类都加载完；首次主动使用时通常触发初始化。
- **层次委派**：默认遵循双亲委派，兼顾一致性与安全性。
- **可扩展性**：可通过自定义加载器从网络、数据库、加密包等来源加载类。
- **隔离性**：不同加载器可形成隔离边界，适用于插件或容器。

面试补充：`Class.forName()` 默认会初始化类；`ClassLoader.loadClass()` 通常只加载，不一定立即初始化。
