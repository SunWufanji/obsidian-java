# Spring Cloud

> 本页先归档本批视频中出现的 Spring Cloud 题目，后续微服务题继续在此扩展。

## 1. Spring Cloud 中的服务注册与发现机制是什么？

服务实例启动时向注册中心（如 Nacos、Consul、Eureka）注册自身地址和元数据，并通过心跳维持租约；消费者从注册中心获取可用实例列表，再结合负载均衡发起调用。它解决了多实例、动态上下线环境中“调用方如何找到服务”的问题。

⚠️ 注册中心发现的是实例列表，不替代超时、重试、熔断等调用容错设计。

## 2. Spring Cloud Config 如何工作？

配置中心把应用配置集中存储（常见后端是 Git 或数据库）。客户端启动时按应用名、环境、分支等维度拉取配置；需要动态刷新时可配合消息通知和刷新机制。敏感配置应加密或交给专用密钥系统，不能因为“集中”就默认安全。

## 3. Spring、Spring Boot 与 Spring Cloud 的关系是什么？

Spring 提供 IoC、AOP、MVC 等基础能力；Spring Boot 通过自动配置和 Starter 简化单个服务开发；Spring Cloud 基于 Boot 组合分布式组件，解决服务注册发现、配置、网关、容错和可观测性等问题。三者是层层构建的关系，不是互相替代。
