# 线程基础

> 这一章后续归档：进程与线程、线程优先级与状态、创建方式、中断与安全终止、线程通信、`ThreadLocal`。

## 1. Java 中如何正确、安全地停止一个线程？

不要使用已废弃的 `Thread.stop()`：它会粗暴终止线程，可能让锁和业务状态停在不一致的中间位置。

正确做法是**协作式停止**：用 `interrupt()` 发出中断请求，任务在合适的位置检查 `isInterrupted()`；若在 `sleep`、`wait`、`join` 中被中断，会收到 `InterruptedException`，通常应恢复中断标记或结束任务。

```java
while (!Thread.currentThread().isInterrupted()) {
    // 处理一小段可中断任务
}
```

大白话：不是把正在干活的人强行拽走，而是通知他“干完手里的可安全收尾的步骤就下班”。

⚠️ `suspend()` / `resume()` 同样已废弃：暂停时可能仍持有锁，其他线程会永久卡住。需要暂停/恢复时使用状态标志配合 `Condition`、`wait/notify` 或更高层任务协调工具。

## 2. 什么是 `ThreadLocal`？它如何工作、适合什么场景？

`ThreadLocal` 给每个线程准备一份独立变量副本。表面上大家都调用同一个 `threadLocal.get()`，实际上线程 A 拿到 A 自己的数据，线程 B 拿到 B 自己的数据，不会互相覆盖。

常见用途：保存当前请求的用户上下文、链路追踪 ID、日期格式化器等线程内上下文。它不是共享数据的线程安全方案，而是**不共享**来避免竞争。

⚠️ 在线程池中线程会被复用，任务结束必须 `remove()`；否则旧请求的数据可能泄漏给下一次任务，也可能造成内存泄漏。

## 3. `Thread.join()` 有什么作用？

`join()` 让当前线程等待目标线程执行结束。例如主线程启动两个子任务后调用它们的 `join()`，可以确保子任务完成后再汇总结果。

它像“等同事把他的部分交付后，你再继续”。`join()` 可被中断，也支持超时版本；它不是用来长期阻塞 Web 请求的工具，复杂异步编排通常用线程池、`Future` 或 `CompletableFuture`。

## 4. 如何正确使用 `wait()` 和 `notify()`？

它们用于同一把对象锁上的线程协作：条件不满足时，消费者 `wait()` 释放锁并等待；生产者修改条件后 `notifyAll()` 唤醒等待者。

```java
synchronized (queue) {
    while (queue.isEmpty()) {
        queue.wait();
    }
    queue.remove();
}
```

必须在 `synchronized` 内调用；必须用 `while` 而不是 `if`，因为可能出现虚假唤醒或被唤醒后条件又被其他线程抢先改变。实际生产者消费者场景更推荐 `BlockingQueue`，它已封装好这些细节。

### 生产者消费者与数据共享补充

生产者负责向共享队列放数据，消费者负责取数据；队列空时消费者等待，队列满时生产者等待。共享数据可以通过对象字段、并发容器、消息队列等传递，但必须明确谁能读、谁能写、何时可见。能使用 `BlockingQueue` 就不要手写复杂的 `wait/notify` 协作。

## 5. `Exchanger` 是什么？

`Exchanger<V>` 用于**两个线程在同一同步点交换数据**。线程 A 调 `exchange(a)` 后等待线程 B，B 调 `exchange(b)` 后两者互相拿到对方的数据。

它像两个人在约定地点互换文件，适合两个任务分阶段处理并交换中间结果的少量场景。它只适合恰好两方，不适合普通消息队列或多消费者场景。

## 6. `Thread` 和 `Runnable` 有什么区别？

继承 `Thread` 是“任务和线程绑死”；实现 `Runnable` 是“只描述要做什么，把谁来执行交给线程或线程池”。Java 单继承，因此业务类通常实现 `Runnable`/`Callable`，再提交给线程池。

`Runnable` 没有返回值、不能直接抛出受检异常；`Callable` 可以返回结果并抛异常，通常配合 `Future` 使用。

## 7. `ThreadLocalRandom` 解决了什么问题？

多个线程共用 `Random` 时，可能竞争内部状态。`ThreadLocalRandom` 让每个线程使用自己的随机数状态，降低高并发下的竞争。

```java
int value = ThreadLocalRandom.current().nextInt(100);
```

它适合并发场景中的普通随机数；安全令牌、验证码等安全敏感随机数仍要用 `SecureRandom`。

## 8. 什么是线程饥饿、活锁？如何避免？

- **饥饿**：线程长期拿不到 CPU、锁或资源，例如高优先级/不停到来的任务持续抢占。
- **活锁**：线程都在运行、也都在互相让步重试，但没有任何实际进展。

避免方式包括：锁粒度合理、避免无限优先级偏向、为重试加入随机退避、限制队列与线程池资源、使用超时和监控告警。它们与死锁不同：死锁是大家都卡住不动；活锁是大家忙着动却做不成事。

## 9. `Thread.yield()` 有什么作用？

`yield()` 只是向调度器提示“我愿意让出本次 CPU 时间片”，调度器可以忽略它，也不保证让给哪一个线程。它不能用于线程同步、不能保证顺序，也不能解决性能问题。

实际业务代码几乎不应依赖它；需要协调任务时用锁、条件变量、线程池或并发工具类。

## 10. Java 线程有哪些状态？

Java 线程状态有：`NEW`、`RUNNABLE`、`BLOCKED`、`WAITING`、`TIMED_WAITING`、`TERMINATED`。

- `BLOCKED`：等待进入 `synchronized` 监视器锁。
- `WAITING`：无限期等待，例如 `wait()`、无超时 `join()`。
- `TIMED_WAITING`：带时间等待，例如 `sleep()`、带超时 `wait()`。

⚠️ Java 的 `RUNNABLE` 同时包含“正在运行”和“已就绪等待 CPU”，不要把它简单等同于操作系统的运行态。

## 11. 守护线程和用户线程有什么区别？

用户线程是执行实际业务的线程；守护线程是为其他线程服务的后台线程，例如 GC 相关线程。JVM 中只剩守护线程时会退出，不会等待守护线程收尾。

因此不能把保存订单、写文件、发消息这类关键业务放在守护线程中，否则 JVM 退出时任务可能来不及完成。可在启动前调用 `setDaemon(true)` 设置，线程启动后不能再修改。
