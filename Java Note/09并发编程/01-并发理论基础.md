# 并发理论基础

> 先理解多线程为什么会出错：多个线程同时读写共享数据时，可能看不到最新值、执行顺序错乱，或同时修改导致结果丢失。

## 1. Java 中的 `volatile` 关键字有什么作用？

### 先说场景

一个线程负责循环处理任务，另一个线程把停止开关改为 `false`。普通变量可能被工作线程一直读到旧值，导致任务停不下来。

```java
private volatile boolean running = true;

public void run() {
    while (running) {
        // 持续处理任务
    }
}
```

### 大白话理解

每个线程可能把变量暂时放在自己的“草稿纸”上。`volatile` 要求写完后及时让其他线程看见，读取时也优先拿最新值。

### 它保证什么

1. **可见性**：一个线程写入后，其他线程随后读取能看到新值。
2. **有序性**：通过内存屏障禁止部分危险的指令重排序。
3. **不保证复合操作原子性**：`count++` 是读、改、写三步，多线程仍可能丢失更新。

### 实际使用与易错点

适合停止标记、配置刷新标记和安全发布。计数器、库存、余额等“读改写”操作要使用 `synchronized`、`Lock` 或原子类。

⚠️ 口诀：**volatile 管看得见和不乱序，不管抢着改。**

## 2. `synchronized` 是什么？它如何工作？

### 大白话理解

`synchronized` 像厕所门锁：线程拿到锁才能进入临界区，其他线程只能排队，因此同一时刻只有一个线程修改共享数据。

```java
public synchronized void decrementStock() {
    stock--;
}
```

### 工作原理

- 修饰实例方法，锁当前对象 `this`。
- 修饰静态方法，锁该类的 `Class` 对象。
- 修饰代码块，锁括号中指定的对象。
- 进入同步区域前获取对象监视器（monitor），退出时释放；释放锁前的修改，对随后获得同一把锁的线程可见。
- 它是可重入的：同一线程持锁后可以再次进入。

### 实际使用与易错点

适合保护小而明确的临界区，例如扣库存、更新内存状态。不要在同步块里执行慢 SQL、远程调用或长 I/O，否则其他线程都会被阻塞。

⚠️ 它锁的是对象或类，不是方法名；两段代码只有锁同一个对象才会互斥。

## 3. 什么是 CAS？它如何实现无锁编程？

### 大白话理解

CAS 是 Compare-And-Swap（比较并交换）：如果当前值还是我预期的 A，就改成 B；如果已被别人改了，就失败并重试。它像“先确认门牌号没变，再把新信塞进去”。

```java
AtomicInteger count = new AtomicInteger(0);
count.incrementAndGet();
```

原子类内部通常会循环 CAS：比较当前值与预期值，相同才更新；不同说明有竞争，再读取最新值重试。

### 优点与问题

- 不必让竞争失败的线程挂起，竞争不激烈时吞吐量较高。
- **ABA 问题**：值 A 变 B 又变回 A，CAS 可能看不出中间变化；可用带版本号的 `AtomicStampedReference`。
- 高竞争时会反复自旋，浪费 CPU。
- 多个变量需要同时保持一致时，通常仍要锁或更高层协调。

⚠️ 无锁不等于一定更快，竞争很激烈时自旋可能不如互斥锁。

## 4. Java 内存模型中的 happens-before 原则是什么？

### 大白话理解

happens-before 不是“现实时间上谁先执行”，而是“前面的结果对后面的操作一定可见，而且顺序不能被破坏”的规则。它像并发程序里的官方交接单：拿到交接单的人，必须能看到前一个人已完成的内容。

常见规则：

1. **程序顺序规则**：同一线程内前面的操作 happens-before 后面的操作。
2. **监视器锁规则**：同一把锁的解锁 happens-before 随后的加锁。
3. **volatile 规则**：对同一 `volatile` 变量的写 happens-before 随后的读。
4. **线程启动规则**：`Thread.start()` happens-before 新线程中的操作。
5. **线程终止规则**：线程内操作 happens-before 其他线程 `join()` 成功返回。
6. **传递性**：A happens-before B，B happens-before C，则 A happens-before C。

它是理解可见性、有序性、锁和 `volatile` 的总规则；面试不要只背定义，要能举出“解锁后下一个拿到同一把锁的线程能看到修改”的例子。

## 5. `synchronized` 和 `volatile` 的用途有什么不同？

两者都与可见性有关，但解决的问题不同：

| 对比 | `volatile` | `synchronized` |
| --- | --- | --- |
| 可见性 | 保证 | 保证 |
| 有序性 | 保证一定的禁止重排语义 | 加锁/解锁形成 happens-before |
| 原子性 | 不保证复合操作 | 保证同一把锁保护的临界区互斥执行 |
| 适用 | 状态开关、一次赋值 | 计数、扣库存、复合状态更新 |

大白话：`volatile` 像公告栏，所有人都能及时看到最新通知；`synchronized` 像办事窗口，一次只让一个人修改材料。`i++`、余额转账必须选后者或原子类，不能只靠 `volatile`。

## 6. 什么是 Java 内存模型（JMM）？它对并发有什么影响？

JMM 是 Java 规定的多线程读写共享变量的规则，不是 JVM 堆、栈等运行时内存区域。它解释了为什么“一个线程已经改了变量，另一个线程却可能看不到”。

线程可以有自己的工作内存和 CPU 缓存，不会每次都直接从主内存读取；编译器和 CPU 还可能为了性能重排序指令。因此并发代码会出现三类问题：**可见性**、**原子性**、**有序性**。`volatile`、锁、原子类和并发工具类，本质上都是按 JMM 规则建立正确的线程间协作。

⚠️ 别把 JMM 和 JVM 内存区域混为一谈：前者是并发语义规范，后者是程序运行时的内存划分。

## 7. 并发中如何保证操作的原子性？

原子性表示一个操作要么全部完成，要么完全没发生，中间不能被其他线程看见。例如 `count++` 并非原子，`count` 读出来、加一、写回的过程中可能被另一个线程插入。

常用方案：

- 使用 `synchronized` 或 `Lock` 包住临界区；
- 单变量计数使用 `AtomicInteger` 等原子类；
- 多个对象或数据库操作需在更高层使用事务、锁或消息一致性方案。

选择原则：共享状态简单时优先原子类；多个字段必须一起变化时使用锁保护整体不变量。

## 8. Java 原子类有哪些用途？

原子类位于 `java.util.concurrent.atomic`，常见有 `AtomicInteger`、`AtomicLong`、`AtomicReference`、`AtomicStampedReference`，底层主要依赖 CAS。

它们适合高并发计数、状态机的单值更新、引用替换等。例如接口访问次数统计可用 `AtomicLong.incrementAndGet()`。`LongAdder` 在高竞争计数时通常比 `AtomicLong` 更能分散竞争，但它读取总值时并不是严格瞬时一致快照。

⚠️ 原子类只保证其封装操作的原子性，不能自动保证“修改 A 后再修改 B”这一整套业务逻辑的原子性。

## 9. Java 中如何实现线程安全？

线程安全的目标是：多个线程按任意交错顺序执行，结果仍符合业务预期。常用思路有四类：

1. **不共享**：局部变量、方法参数、`ThreadLocal`，每个线程各用各的。
2. **不修改**：使用不可变对象，例如 `String`、不可变配置对象。
3. **协调修改**：用 `synchronized`、`Lock`、原子类或并发容器保护共享状态。
4. **正确发布**：让其他线程能看到一个初始化完成的对象。

实际开发先问“数据是否真的需要共享”，能不共享就不共享；这通常比事后加锁更简单可靠。

## 10. 不可变对象如何解决并发读写问题？

不可变对象创建后内部状态永远不变，例如 `String`、`Integer`、`LocalDateTime`。多个线程同时读它不会产生竞争，因为根本没有“写”的动作。

自定义不可变类通常要做到：类或关键字段不可变、字段使用 `final`、不提供修改方法、可变成员返回防御性副本。更新时创建新对象替代旧对象，而不是修改原对象。

大白话：多人可以同时读一本已经印刷完成的书；一旦要改内容，就印一本新版本，不在原书上同时涂改。

## 11. 什么是对象的安全发布？

安全发布是指一个对象构造完成后，其他线程能看到它完整、正确的状态，而不是只看到一半初始化的数据。

常见安全发布方式：通过静态初始化、放入线程安全容器、在加锁后写入并在同一把锁保护下读取、写入 `volatile` 引用、使用 `final` 字段正确构造。单例、配置对象、共享缓存对象都要考虑这个问题。

## 12. 如何实现线程安全的单例？

最推荐的是**枚举单例**或**静态内部类单例**：代码简单，利用类加载机制保证初始化只执行一次。

```java
public class Singleton {
    private Singleton() {}
    private static class Holder {
        private static final Singleton INSTANCE = new Singleton();
    }
    public static Singleton getInstance() { return Holder.INSTANCE; }
}
```

双重检查锁也可行，但实例引用必须是 `volatile`，否则可能发生“引用已经赋值、对象却尚未完全初始化”的重排序问题。
