# 并发安全容器

> 这一章后续归档：`ConcurrentHashMap`、`CopyOnWriteArrayList`、`ConcurrentLinkedQueue`、`BlockingQueue` 及它们的线程安全原理和适用场景。

## 1. Java 常见并发集合有哪些？如何选择？

并发集合用于多个线程同时读写集合时，避免自己手写锁。

- `ConcurrentHashMap`：高并发键值存储，最常用。
- `CopyOnWriteArrayList`：读多写极少的列表。
- `ConcurrentLinkedQueue`：非阻塞队列。
- `BlockingQueue`：生产者消费者队列，队列空/满时能阻塞等待。

不要为了“线程安全”就随便把所有集合换成并发集合；先看数据是读多写少、是否需要阻塞、是否要按 key 查询，再选匹配实现。

## 2. `BlockingQueue` 如何用于并发编程？

阻塞队列是生产者消费者模型的常用工具：队列空时消费者 `take()` 会等待；队列满时生产者 `put()` 会等待。它把 `wait/notify`、条件检查和唤醒细节封装好了。

常见实现：有界数组队列 `ArrayBlockingQueue`、可选界链表队列 `LinkedBlockingQueue`、无存储交接队列 `SynchronousQueue`。线程池的工作队列就是它的重要应用。

⚠️ 队列容量必须有意识地设置：无界队列可能让任务无限堆积直到内存耗尽；过小队列又会频繁触发拒绝策略。

## 3. `SynchronousQueue` 是什么？

`SynchronousQueue` 容量为 0，不真正保存元素。生产者放入一个任务时，必须正好有消费者来接；否则生产者等待，反之亦然。

它像“当面交接”，适合任务不希望排队、而是希望立即交给线程处理的场景。`newCachedThreadPool` 常使用它，因此高流量下可能快速创建大量线程，生产中要谨慎。

## 4. `CopyOnWriteArrayList` 和 `Vector` 有什么区别？

`Vector` 是每次操作大多直接加锁；`CopyOnWriteArrayList` 在写时复制整个底层数组，读操作基本不加锁。

因此 `CopyOnWriteArrayList` 适合“读很多、写很少”的订阅者列表、监听器列表。写入频繁或列表很大时，每次复制数组成本高，不适合使用。它的迭代器是快照视图，遍历期间不一定看到最新写入。

## 5. `ConcurrentHashMap` 如何实现线程安全？

`ConcurrentHashMap` 允许不同桶/节点上的操作尽可能并发，读操作通常不需要全表加锁；写入冲突时只锁更小粒度的结构，并结合 CAS。

大白话：它不是给整张表上一把大锁，而是尽量只锁正在修改的那一小格，因此多个线程改不同 key 时可以并行。⚠️ 它不允许 `null` key 或 `null` value，因为并发场景中无法区分“没查到”与“值就是 null”。
